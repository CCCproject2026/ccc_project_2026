# testing-and-verification

## 目的・使用場面

テスト計画、変更後の検証、Agent設定の読込確認。変更の受入条件に対応する検証を選び、実行結果と未検証範囲を再現可能に記録する。

## 使用しない場面

実環境への無断publishやDB更新、存在しないテスト基盤の仮定。

## 事前調査

リポジトリルート基準で `AGENTS.md` と docs/agent-coding/commands.md、main/web/package.json、main/ai/Makefile、.github/workflows/、関連Test Plan、接続先 を必要な範囲だけ読む。以下のパスはすべてリポジトリルート基準。情報が未確認なら推測せず記録する。

## 実行手順

1. 受入条件ごとに静的/単体/結合/実機のどの証拠が必要か決める。
2. 合成データと隔離環境を使い、必要な正常/境界/異常ケースを実行する。
3. コマンド・cwd・終了コード・結果・未実行理由を記録する。
4. Agent設定はsync --checkと、各クライアントの発見→本文読込→明示呼出→適用を分けて確認する。

## 成果物

検証表、実行コマンド、残存リスク/必要環境

## 検証

期待する振舞いを確認し、単に実装の文字列を照合するだけで完了にしない。再実行は変更/失敗/未解決の懸念に対応する範囲。

## よくある失敗

lintをE2Eと扱う、モデルfixture未提供で互換性成功と記載、過去のログを今回の結果とする。

## 必要時の参照

検証コマンドは `docs/agent-coding/commands.md`、領域間契約の現状は `docs/agent-coding/investigation.md`、レビューと承認は `docs/agent-coding/workflow.md`。すべてを常時読み込まず対象Taskに必要なものだけ読む。
