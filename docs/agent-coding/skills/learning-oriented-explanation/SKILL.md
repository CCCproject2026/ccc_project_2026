# learning-oriented-explanation

## 目的・使用場面

実装完了の技術解説、引継ぎ、設計理由の説明。実装後に日本語で変更理由と仕組みを実コード例から説明し、検証結果と学習点を伝える。

## 使用しない場面

コード変更のない短い質問に長い完了報告を強制する場合。

## 事前調査

リポジトリルート基準で `AGENTS.md` と 実際の差分、設計判断、実行コマンド・結果、対象コードの具体例 を必要な範囲だけ読む。以下のパスはすべてリポジトリルート基準。情報が未確認なら推測せず記録する。

## 実行手順

1. AGENTS.mdの必須8項目で説明する。
2. 前後の振舞い、なぜ必要か、入口から出口への処理とデータの流れを結ぶ。
3. 選ばなかった案の利点/欠点も短く説明する。
4. 専門語を定義し、実在する関数/ファイルを例にする。
5. 成功/失敗/スキップ/未実行を分け、実践的な学習点を2〜5個提示する。

## 成果物

日本語の8項目報告。Task規模に応じた分量。

## 検証

差分/ログにない成果を記載していないか、コード例が実在するか照合する。

## よくある失敗

用語だけで説明、未実行を省略、初心者を見下す、一般論だけで実装との関係がない。

## 必要時の参照

検証コマンドは `docs/agent-coding/commands.md`、領域間契約の現状は `docs/agent-coding/investigation.md`、レビューと承認は `docs/agent-coding/workflow.md`。すべてを常時読み込まず対象Taskに必要なものだけ読む。
