# code-review

## 目的・使用場面

PR/差分の独立レビューを依頼されたとき。実装者から独立して差分を読み、再現可能な不具合・契約違反・検証不足を根拠付きでレビューする。

## 使用しない場面

実装者の自己点検だけを独立レビューと称する場合、無関係な全面改修。

## 事前調査

リポジトリルート基準で `AGENTS.md` と AGENTS.md、git status/diff、対象コードと呼出経路、Task受入条件、契約と実行ログ を必要な範囲だけ読む。以下のパスはすべてリポジトリルート基準。情報が未確認なら推測せず記録する。

## 実行手順

1. docs/agent-coding/roles/senior-code-reviewer.mdを読む。
2. 未追跡の新規ファイルも確認し、実装者の成功報告をコード/ログで検証する。
3. docs/agent-coding/workflow.mdの全レビュー観点を対象範囲に適用する。
4. 修正を行わず、根拠のある指摘と未検証を報告する。

## 成果物

Severity、ファイル:行、問題/理由/シナリオ/修正/学習ポイント。指摘なしでも範囲と限界。

## 検証

必要に応じ読み取り検証を再現。外部通信/DB変更はレビューに含めない。修正後は別差分を再レビュー。

## よくある失敗

説明だけを信頼、コード位置のない一般論、テスト未実行を成功と扱う、担当外の好みだけを重大指摘にする。

## 必要時の参照

検証コマンドは `docs/agent-coding/commands.md`、領域間契約の現状は `docs/agent-coding/investigation.md`、レビューと承認は `docs/agent-coding/workflow.md`。すべてを常時読み込まず対象Taskに必要なものだけ読む。
