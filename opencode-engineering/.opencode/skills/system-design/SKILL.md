# System design
1. Extract requirements and constraints; label assumptions.
2. Read owning source, API/data contracts, deployment config, and relevant design docs.
3. Map components, trust boundaries, flows, state ownership, failure behavior, and scaling constraints.
4. Compare viable alternatives against reliability, security, cost, complexity, and reversibility.
5. Document decisions, consequences, open questions, migration/rollback, and verification.
Never promote an unconfirmed interface into a contract. Output a compact design with paths and evidence.
