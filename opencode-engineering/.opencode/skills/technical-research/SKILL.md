# Technical research
1. Prefer official docs, source code, release notes, and primary papers. Record access date and URL.
2. Check current version, date, license, and compatibility claims directly; distinguish measured facts from inference.
3. Compare implementation details and failure/security model, not popularity alone.
4. Summarize only supported claims; mark inaccessible or unverified details.
5. Never execute downloaded code or install a tool during research without need and source review.
Output: question, findings, comparison, recommendation, caveats, and citations.
