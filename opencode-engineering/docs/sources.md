# Sources and external asset review

Research date: 2026-11-18. GitHub star counts and update times are volatile; where an authoritative exact snapshot was unavailable, this document does not invent a number. Stars are not a quality score. No external skill text or source code was copied; only broad workflow ideas were independently expressed here. License status must be rechecked before any future incorporation.

## OpenCode primary sources

| Source | Findings / use | License / risk |
|---|---|---|
| [OpenCode docs](https://opencode.ai/docs/) | Current V2 docs describe JSON/JSONC config, Markdown custom agents, skill discovery, MCP, permissions, commands, plugins. Project-local paths are used here. | Official docs. Configuration is not an OS security boundary. |
| [anomalyco/opencode](https://github.com/anomalyco/opencode) | Official runtime; repo page showed 226k+ stars and MIT. Source defines actual behavior and schema; CLI 1.19.6 is installed locally. | MIT. Rapidly changing; use schema and CLI matching installed version. |
| [awesome-opencode](https://github.com/awesome-opencode/awesome-opencode) | Discovery catalog for plugins, themes, agents and resources. | CC0 1.0 stated in README; catalog entries require individual review. Star counts and listing inclusion do not establish safety. |

For every project above, the sources reviewed included the GitHub README, repository/license metadata when available, and representative configuration or skill structure. Detailed security audit of every script, transitive package, or skill is out of scope; the adoption choice is therefore deliberately conservative.

This is a source-level design review, not a complete audit of every file, dependency, release, or historical commit in each repository. OpenCode runtime source, representative READMEs/config formats, and license declarations were examined through linked primary pages. Full star/update/license matrix refresh is a maintenance task; use GitHub API and exact commit references before adopting external artifacts.
